# Stage C, wave 3: every remaining rule and legacy button

Goal: the APEX application does everything the legacy Forms screens did (except ZATCA / RSD and printer selection).
Wave 1 rebuilt the process screens, wave 2 the rules of the main transaction screens. Wave 3 covers:

* **the rules of the 157 screens generated from structure only** (`app\gen\out\specs.json`, specs without `rules` / `proc`):
  setup and master-data screens, privileges, and a few documents;
* **the buttons and features recorded as "not reproduced"** in `app\legacy\processes\*.md` of the screens already done.

Read first: `STAGE_C_CONTRACT.md` (process pages, evidence), `STAGE_C_RULES_ADDENDUM.md` (rules), `STAGE_C_ACTIONS_ADDENDUM.md`
(buttons), and the root `README.md`. Evidence packs exist for every screen in `app\legacy\evidence\<FORM>.md`.

## What to deliver per screen

1. `app\legacy\processes\<FORM>.md`. Create it, or update it when it already exists. It holds:
   * the rules and buttons of the legacy screen, the evidence each one rests on, and a confidence rating;
   * a final section `## Coverage` that states what is reproduced and what is deliberately not reproduced, with the reason
     for each (for example Forms-only mechanics, dead code, or a feature switched off in the data).

   A screen that has **no business rules** beyond its table (a plain code table) still gets a short `.md` that says so, with
   the evidence you checked. The coverage check counts these files.
2. The implementation, using only the mechanisms below. PL/SQL goes into **your own package file** (see ownership).
3. Tests on the build copy that always end with ROLLBACK. Cover each rule and button. Where a button creates documents,
   run the whole flow inside a simulated APEX session as well: set `APP_ID` / `G_*` with `apex_session.create_session`, or use
   the technique of the existing `t_conv.py`, so that the generated `APPX_*` triggers are active.

## Mechanisms (all generated by `app\gen`; do not edit the generator)

In `app\legacy\overrides\<FORM>.json`:

```json
{"pattern": "AUTO",
 "rules": {
   "key_expr": {}, "row_rules": {}, "validations": [], "after_save": [], "defaults": {}, "readonly": [], "hidden": [],
   "optional": [], "where": "...",
   "add_columns": {"ST_TRNS_DET.EXPIRY_DATE": {"label_a": "تاريخ الصلاحية", "label_e": "Expiry date"}},
   "soft_delete": {"set": {"DELETE_FLAG": "1", "DELETE_USER": ":G_USER_CODE", "DELETE_DATE": "sysdate"},
                   "lines": "keep", "check": "PL/SQL function body returning error text or null; page items as :PAGE_<COL>",
                   "message_a": "تم حذف المستند"},
   "warnings": [{"name": "...", "plsql": "function body returning a warning text or null (legacy 'continue?' alert); :PAGE_<COL>, :PAGE_ROWID",
                 "when": "CREATE,SAVE"}],
   "info": [{"name": "BAL", "label_a": "رصيد العميل", "label_e": "Customer balance",
             "sql": "select to_char(get_customer_bal_all(:PAGE_CUSTOMER_CODE), 'FM999G999G990D00') from dual"}]
 },
 "actions": [ ... see STAGE_C_ACTIONS_ADDENDUM.md ... ]}
```

* **Rule keys from wave 2:** `key_expr`, `row_rules`, `validations`, `after_save`, `defaults`, `readonly`, `hidden`, `optional`
  and `where`, as in `STAGE_C_RULES_ADDENDUM.md`.
* **`add_columns`** (new) shows a hidden column, or adds a table column the generator did not place. The labels are optional.
* **`soft_delete`** (new): the Delete button flags the document instead of removing it, as the legacy did. `lines` is `keep`
  or `delete`.
  * Works on document and pop-up form pages.
  * Add the matching filter to `where`, for example `nvl(DELETE_FLAG, 0) = 0`, when the legacy list hid deleted documents.
* **`warnings`** (new): before Save or Create the page asks the server for these texts. When one is returned, the user sees
  it and confirms ("هل تريد الاستمرار؟") before the page submits.
  * Use these for legacy alerts that asked "continue?". Errors that refused the save stay validations or row rules.
  * Works on document and pop-up form pages.
* **`info`** (new): read-only values the legacy screen displayed, such as balances, running totals ("DEBIT_TOTAL /
  CREDIT_TOTAL / DIFF"), store balance, or status texts like "تم عمل تسوية جرد ...".
  * Shown in a panel above the lines of a saved document. Each is one SQL query returning one value; use `:PAGE_<COL>` and
    `:PAGE_ROWID`.
  * The values refresh when the page reloads after each save.
  * Works on document pages.
* **`actions`** (buttons) work on document pages, pop-up form pages and grid pages.
  * Grid pages have no record, so do not use `:PAGE_*` there.
  * Parameter types are `date`, `number`, `text` and (new) **`file`**. A file parameter passes the uploaded file's name. Read
    the file with `select blob_content, filename from apex_application_temp_files where name = :NAME`, and parse Excel or
    CSV with `apex_data_parser.parse(p_content => blob, p_file_name => filename)`. Use this for the legacy "load from Excel"
    buttons (WEBUTIL).
  * `message` is an optional PL/SQL expression shown as the success text.
* **Process pages** (`pattern: PROCESS`, `proc` block, as in `STAGE_C_CONTRACT.md`) are for batch operations that are not
  tied to one document.
* **Grid pages save their rows in the background**, so page validations and after-save processes do not run for them. Put
  grid rules in `row_rules` (the generated `BEFORE INSERT OR UPDATE` trigger), in `key_expr`, and in a delete hook if the
  legacy refused deletes (see the delete triggers in `21_rules_st.sql`).

If a legacy feature needs something these mechanisms cannot express, do not work around it in the generator. Record it in
the `.md` and in your final report; the main session extends the generator.
