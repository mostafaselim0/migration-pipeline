# Stage C contract: reconstructing legacy process screens for the APEX app

Context: ASCON ERP (Oracle Forms/Reports 11g, Arabic/English, schema SMART) is being migrated to Oracle APEX 24.2, app 100 in
workspace SMART on this server (Oracle 19c PDB `ORCLPDB`, `localhost:1521/ORCLPDB`). The APEX app is generated by
`C:\Smart Transformation\app\gen\build.py` from specs. Screens the generator could not map to tables are "PROCESS" pages and need
their logic reconstructed. Evidence for each form is in `app\legacy\evidence\<FORM>.md` (registry rows, labels, SQL found in the
compiled .fmx, .fmb triggers when source exists, referenced .pll library procedures, table metadata, existing DB triggers).
Full .pll text dumps are in `app\legacy\pll\`. Existing DB code (384 units, triggers) in SMART is the other main source:
query `user_source`, `user_triggers`, `user_objects`.

## What you deliver per form

1. `app\legacy\processes\<FORM>.md` — the extracted rules: purpose, inputs, what the legacy form reads/writes (tables, columns),
   validations, derivations, postings, the evidence each rule rests on, open questions, and a confidence rating (high/medium/low).
2. One of:
   a. **Screen correction** (the form is really a data-entry/setup screen): `app\legacy\overrides\<FORM>.json`
      ```json
      {"pattern": "GRID | REPORT_FORM | MASTER_DETAIL", "master": {"table": "TABLE_NAME"},
       "details": [{"table": "CHILD_TABLE", "join": [["CHILD_COL", "MASTER_COL"]], "title_a": "...", "title_e": "..."}],
       "where": null, "insert": true, "update": true, "delete": true, "notes": "one line: why"}
      ```
      Columns, labels and LOVs are derived automatically from the tables and GN_FORM_ITEM.
   b. **Process screen**: PL/SQL in a package, file `app\db\20_proc_<module>.sql` (module = gl, st, ar, vn, tx, se), compiled
      into SMART, plus `app\legacy\overrides\<FORM>.json`:
      ```json
      {"pattern": "PROCESS", "notes": "...",
       "proc": {"procedure": "app_proc_gl.post_entries",
                "description_a": "Arabic explanation shown on the page", "description_e": "English",
                "params": [{"name": "FROM_YEAR", "arg": "p_from_year", "label_a": "...", "label_e": "...",
                            "type": "number|date|text|check", "required": true,
                            "lov_sql": "select display d, value r from ...  (optional, may use :G_COMPANY_CODE etc.)",
                            "default": "optional", "default_type": "STATIC|ITEM|EXPRESSION"}],
                "fixed_args": {"p_company_code": "to_number(:G_COMPANY_CODE)", "p_user_code": "to_number(:G_USER_CODE)",
                               "p_password_number": "to_number(:G_PASSWORD_NUMBER)"},
                "button_a": "ترحيل", "button_e": "Post",
                "confirm_a": "Arabic confirmation question (optional)", "success_a": "Arabic success message",
                "preview_sql": "optional SELECT shown under the parameters (may reference :P<page>_<NAME> items... leave null if unsure)",
                "preview_columns": [{"name": "COL", "label_a": "...", "type": "NUMBER|STRING|DATE"}]}}
      ```
      Application items available to PL/SQL through `v('G_USER_CODE')`, `v('G_COMPANY_CODE')`, `v('G_PASSWORD_NUMBER')`,
      `v('G_LANG')` ('ar'|'en'). Raise business errors with `raise_application_error(-20100..-20199, '<Arabic message>')`.
   c. **Cannot reconstruct** (evidence insufficient): only the `.md` with what is known and the exact questions for the key user
      or vendor. Do not invent logic.

## Rules

- Work only on the build copy (ORCLPDB on localhost). Never connect to 37.27.226.117 (production).
- Run SQL with `powershell -File "C:\Smart Transformation\app\tools\runsql.ps1" <file.sql>` (connects as SMART, UTF-8) or with Python
  (`sys.path.insert(0, r"C:\Smart Transformation\app\tools"); from db import connect; c = connect()`).
- You may test procedures, but every test must end with ROLLBACK; leave no data changes behind. Do not commit inside procedures
  except where the legacy logic clearly committed per batch (document it); prefer letting APEX commit.
- Package procedures must be idempotent-safe: validate inputs, refuse double posting, lock rows (`for update`) where the legacy did.
- Do not edit anything under `app\gen`, `app\build`, `app\export` or the APEX app itself. Only write `app\legacy\processes\*`,
  `app\legacy\overrides\*` and `app\db\20_proc_*.sql`.
- UTF-8 everywhere. Do not round-trip files through PowerShell Get-Content/Set-Content (it corrupts Arabic); use Python or the file tools.
- Prefer faithful reproduction of the legacy behaviour over improvement; note improvements as suggestions.
- Report at the end: per form, which deliverable (a/b/c), confidence, and what a human must verify.
