## Legacy rules (evidence: embedded SQL + messages + wave 3 analysis)

1. `SELECT PASSWORD FROM USERS WHERE USERS_CODE = :user` compared with `ENCODE_PASSWORD(old password)` -> "كلمة السر القديمة غير مطابقة" /
   "Old Password is not correct". The form program unit `ENCODE_PASSWORD(IN_PASSWORD)` (TEMP_PASSWORD, loop I) is the algorithm of the wrapped DB
   function `ENCODE_PASSWORD`: the ASCII codes of the characters (`'0'` -> `'48'`, `'12'` -> `'4950'`). Verified on the build copy: every
   `USERS.PASSWORD` value is such a code string (17/17), 12 users hold `ENCODE_PASSWORD('0')`.
2. New password and confirmation are mandatory -> "لابد من وضع كلمة سر وتأكيدها" / "A Confirmed new password must be entered".
3. Confirmation must match -> "تأكيد كلمة السر غير مطابق لكلمة السر الجديدة".
4. `UPDATE USERS SET PASSWORD = ENCODE_PASSWORD(:new) WHERE USERS_CODE = :user`.
5. The company LOVs (`COMPANY` / `GROUP_COMPANY` / `GROUP_USERS`) are the login template's company switcher, not part of the password change.

## Page 9998 equivalence

Page 9998 has current / new / confirm items (all required), validation new = confirm, and `app_sec.change_password`, which checks the current
password, requires 6+ characters and a different password, and stores a salted hash in `APP_USER_AUTH`. Rules 1-3 are covered (stricter).

## Consistency with the users screen (ACGROUP_USERS, wave 3)

A password typed or reset ("تصفير كلمة السر") by the administrator in ACGROUP_USERS is stored the legacy way (`ENCODE_PASSWORD` in USERS.PASSWORD)
and becomes the user's one-time APEX password (APP_USER_AUTH hash, MUST_CHANGE = 'Y', unlocked) - see `processes\ACGROUP_USERS.md`.

## What must be changed outside this agent's files (APP_SEC, `app\db\01_app_core.sql`)

- `app_sec.authenticate` (first login of a user without APP_USER_AUTH hash) compares `USERS.PASSWORD = p_password` in plain text. The stored value
  is encoded, so the legacy password is refused; only the encoded digits work. Fix: `l_usr.password in (p_password, encode_password(p_password))`.
- `app_sec.change_password` does not update `USERS.PASSWORD` (rule 4). While Forms runs in parallel, a password changed in APEX does not change the
  Forms password. Fix if coexistence matters: also `update users set password = encode_password(p_new)`.
